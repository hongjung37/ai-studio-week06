## 1. 과업 정의

- 선택: (나) 리뷰 분류
 
- 분류 항목과 긴급도 기준: [배송/품질/가격/서비스/기타]로 분류하며 부정적인 부분과 가장 가까운 카테고리로 분류한다. 또한  리뷰가 부정적이고 , 부정적인 요소에 대한 대응 필요 속도에 의해 긴급도가 결정된다.

   - 구체적인 평가 기준 
     -  1: 개선할 점이 없거나 단순 칭찬, 만족, 일반 의견일 경우
     -  2: 개선할 점이 있으나 대응이 시급하지는 않은 경우 (경미한 불만, 개선요청 등)
     -  3: 개선할 점이 있고 대응이 시급한 경우 (심각한 하자, 파손등)
    
- 출력 형식: {"type": ..., "urgency": ...}

## 3. 프롬프트 전문

### Zero-shot
```
[분류 유형]
- 배송, 품질, 가격, 서비스, 기타 중 택 1

[분류 기준]
부정적인 부분에 초점을 맞춰 분류한다. 없을 경우 좋은 부분.

[긴급도 기준]
- 1 - 개선할 점이 없거나 단순 칭찬, 만족, 일반 의견일 경우
- 2 - 개선할 점이 있으나 대응이 시급하지는 않은 경우 (경미한 불만, 개선요청 등)
- 3 - 개선할 점이 있고 대응이 시급한 경우 (심각한 하자, 파손등)

[출력 형식]
반드시 다른 설명이나 추가 문장없이 JSON 형식으로만 응답.
{"type": "유형", "urgency": 숫자}

[고객 리뷰]
{INPUT_TEXT}
```

### CoT
```

[출력 형식]
```

## 6. 분석

- **형식 준수**:
  - 모든 기법 100% 준수: Zero-shot, Few-shot, CoT 모두 지시된 JSON 구조({"type": "유형", "urgency": 숫자})를 안정적으로 출력하였다.
  - CoT의 출력 안정성: CoT는 사전에 추론 과정을 거치도록 유도했음에도 지시사항대로 맨 마지막 줄에 단독 JSON만을 출력하여 파싱(json.loads) 과정에서 오류 없이 정상 처리되었다.

- **분류 정확성**:
  - Zero-shot (직관적 키워드 의존): 5개 문항 중 4문항을 맞춰 80%의 정확도를 기록하였다. 명확한 사례(1, 3, 5번)와 '파손'이라는 강한 위험 키워드가 직접 드러난 사례(2번)는 올바르게 분류하였으나, 직접적인 파손 단어 없이 훼손을 나타낸 재포장 이슈(4번)에서는 사태의 심각성을 간과하고 긴급도를 2로 과소평가하는 한계를 보였다. 즉각적인 키워드 유무에 따라 판정 정확도가 좌우되는 경향이 나타났다.
  - Few-shot (예시 기반의 맥락 학습): 5개 문항 중 4문항을 맞추며 80%의 정확도를 기록하였다. 프롬프트에 주입된 예시를 참조하여 Zero-shot이 놓쳤던 재포장 이슈(4번)의 심각성을 파악해 긴급도 3을 도출해냈다. 그러나 '배송 파손'과 '교환 완료/감사'가 공존하는 복합 사례(2번)에서는 제공된 예시 중 긍정/개선 사례의 영향을 받아 사후 조치에 무게를 두며 긴급도를 2로 판정하는 오답이 발생하였다.
  - CoT (단계별 추론을 통한 높은 단일 정확도): 5개 문항 모두 정답과 일치하여 1회차 기준 100%의 가장 높은 분류 정확도를 기록하였다. 1~3단계의 추론 절차를 강제함으로써 문장 내 상반된 감정이 공존하는 사례(2번)와 맥락적 하자가 포함된 사례(4번) 모두에서 표면적인 단어에 휩쓸리지 않고 핵심 부정 요소와 잠재적 심각도를 논리적으로 짚어내어 정답을 도출하였다.
  - 종합: 단일 실행 기준으로는 복합 문맥을 단계별로 분해한 CoT가 가장 높은 정확도를 보였으나, Few-shot 역시 예시를 통해 Zero-shot의 키워드 편향을 상당 부분 보완하며 준수한 분류 성능을 나타냈다.

- **일관성 (반복 실행 분석)**:
  - Zero-shot (단순 키워드 기반의 높은 일관성): 애매 사례(#2) 3회 반복 테스트에서 모두 긴급도 3을 도출하여 100% 일치도를 기록했다. 복잡한 추론 과정 없이 '파손'이라는 핵심 위험 키워드에 집중하여 일관된 결과를 냈다. 그러나 직접적인 파손 키워드가 없던 사례(#4)에서는 문맥을 파악하지 못하고 긴급도를 2로 과소평가하는 한계가 존재했다.
  - Few-shot (경계값 진동 발생): 1회차(긴급도 2)와 2,3회차(긴급도 3) 간 편차가 발생하였다. 제공된 예시들이 엣지 케이스를 판단하는데에 도움을 주지만, '파손(부정)'과 '교환 완료(긍정)'가 충돌하는 경계 조건을 완벽하게 파악하지는 못하였다.
  - CoT (추론 발산으로 인한 낮은 일관성): 동일 입력에 대해 3 -> 2 -> 1로 시도마다 완전히 다른 긴급도가 도출되며 가장 불안정한 결과를 보였다. 다단계 추론을 강제한 결과, 어떤 실행에서는 '파손 발생' 자체의 심각성에 초점을 맞추고, 다른 실행에서는 '이미 대처가 끝났다'는 사후 상태에 가중치를 두어 추론 경로가 발산하는 문제가 발생하였다.

- **비용**:
  - 토큰 소모량: Zero-shot과 Few-shot은 입력 토큰(Few-shot이 약간 더 높음) 대비 출력이 약 20~30토큰 안팎의 순수 JSON으로 끝나 매우 경제적이었다.
  - CoT의 토큰 과소모: CoT는 1~3단계 추론 과정을 전부 텍스트로 생성하느라 출력 토큰이 회당 약 150~250토큰 이상 소모되어, 단순 JSON 출력 대비 출력 비용 및 API 지연 시간(Latency)이 크게 증가하였다.
  - 비용 대 효율 결론: 단순 리뷰 분류 및 데이터 추출 작업에서는 CoT의 높은 비용및 높은 분산 위험을 감수하기보다, Few-shot 기법이 비용 및 성능 측면에서 가장 효율적인 선택임을 알 수 있다.

## 7. 결론 — 우리 팀이 쓸 기본 전략

본 실험을 통해 각 기법별 정확도/일관성/비용 등을 분석할 수 있었다.

1. **기법별 특성 요약**:
   - Zero-shot: 출력 비용과 응답 속도가 가장 우수하나, 모호하거나 복합적인 리뷰에서 강한 단어(키워드 편향)에 의해 문맥을 놓치고 오판하는 한계를 보였다.
   - Few-shot: 명확한 입출력 예시를 통해 경계 케이스의 판단 기준을 모델에 효과적으로 주입함으로써 가장 높은 분류 정확도와 준수한 일관성을 기록하였다.
   - CoT: 추론 과정을 거쳤으나, 애매한 사례에서는 매 실행마다 주목하는 문맥이 달라져 결과 분산(3 → 2 → 1)이 심화되었고, 불필요한 출력 토큰 증가로 지연 시간과 API 비용이 크게 낭비되었다.

2. **최종 결론**:
   5건 기준 정확도는 CoT(5/5)가 가장 높았고 Zero-shot과 Few-shot은 4/5로 같았다. 일관성은 Zero-shot이 가장 좋았고 CoT가 가장 나빴으며, 비용은 Zero-shot < Few-shot < CoT 순이다. 표본이 작아 차이를 맹신할 수는 없다. 그럼에도 Zero-shot이 놓친 재포장 사례(#4)를 Few-shot이 바로잡았고 추가 비용은 작았으므로, 기본 전략은 Few-shot으로 하고 애매한 건만 CoT로 보완한다.
